# 브리프: 시안 9종 2차 리뷰(실제 데이터 반영 후)

작업 폴더 `/data5/CSL_homepage/first_draft/`. 한국어로 쓴다. **읽기 전용 검토**다: 이 보고서와 `site/_shots/` 캡처 외에는 아무 파일도 고치지 않는다.

## 배경
- 9종: `basic`(원본 climate.snu.ac.kr 메뉴 구조를 따른 기본 형식), `t1_classic` ~ `t8_globe`(디자인 시안). 모두 같은 데이터·같은 빌드(`site/<theme>/`, 국문 `site/<theme>/ko/`).
- 1차 리뷰(백업 전, 예시 데이터): `reports/visual_review.md`. 지금은 실제 데이터가 들어갔다. 구성원 22명 + 졸업생 23명(사진 46장), 논문 318편, 공지·뉴스 99편 + 갤러리 앨범 89편(`album: true`), 연구 5개 주제(원본 그림), 영상 15편, 발표 0건.
- 테마 규약과 선택 기능: `themes/THEME_CONTRACT.md`(특히 3-1절). basic만 쓰는 선택 기능이 있다: 구성원 개인 페이지 `member.html`, 연구 주제 페이지 `research_topic.html`, `gallery.html`(앨범을 뉴스 목록에서 분리), `extra_pages`. **다른 8종은 이 기능이 없어서 앨범 89편이 뉴스 목록에 섞이고, 구성원·연구 상세 페이지도 없다.**
- 1차 리뷰의 경미 16건은 아직 고치지 않았다.

## 방법
- 캡처: `node scripts/shot.mjs <theme> [page] [--full] [--ko] [--dark]` → `site/_shots/`. 데스크톱 1440×900과 모바일 390×844가 함께 나온다.
- 테마마다 최소: 홈, people, publications, news(목록), 뉴스 상세 1개(앨범: `news/2025-02-24-snu-kopri-high-latitude-workshop`, 논문 소식: `news/2026-10-23-permafrost-soil-moisture`), research, contact. 국문은 홈·people 정도, 다크는 테마 성격상 필요한 곳만. basic은 `people/yechul-shin`, `research/mechanism`, `gallery`, `about`도 본다.
- 필요하면 `site/<theme>/*.html`과 `themes/<theme>/`의 CSS·템플릿을 읽어 원인을 짚는다.

## 평가 기준
1. 실제 데이터 적합성: 긴 국문 제목·이름, 사진 45장, 논문 318편, 뉴스+앨범 188편, 발표 0건(빈 화면 처리)이 무리 없이 보이는가
2. 정보 구조: 연구실 홈페이지로서 찾고 싶은 정보(연구, 구성원, 논문, 소식, 연락처)에 바로 닿는가. 원본 사이트 메뉴(Introduction/Research/People/Publication/Notice)를 기대하는 사용자 입장도 고려
3. 시각 완성도: 타이포·여백·색·일관성, 국문 표시, 다크모드
4. 모바일
5. 콘셉트의 설득력과 차별성(다른 시안과 겹치지 않는가)
6. 접근성(대비, 키보드, 터치 영역)과 유지보수성

1. 요약표: 테마 × 기준 점수(1~5) + 한 줄 총평. 최종 후보 추천 순위와 이유.
2. 테마별 절:
   - 강점 2~3개
   - 문제 목록(심각/보통/경미, 캡처 파일명·화면 위치·원인 파일/선택자)
   - **v01 방향(정제판)**: 콘셉트를 유지하고 문제를 고치는 구체 작업 목록. 실제 데이터에 맞게 선택 기능(구성원 개인 페이지, 연구 주제 페이지, 갤러리 분리)을 쓸지 판단
   - **v02 방향(확장판)**: 콘셉트를 한 단계 밀어붙이는 구체 기능 2~4개(정적 사이트에서 가능하고 외부 서비스 없이. 이 연구실의 소재 — 엘니뇨, 북극, 탄소순환, 기후모델, 논문·영상 — 와 연결된 것)
