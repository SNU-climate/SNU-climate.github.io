## 지적 (심각도순, 15개 이내)

### 1. [중간] hover로 열린 People 메뉴는 상태가 불일치하고 Esc로 닫히지 않음
- 위치: `themes/t5.v02/assets/style.css:88`, `themes/t5.v02/assets/t5.js:14`
- 문제: CSS `:hover`가 JS 상태와 독립적으로 메뉴를 표시한다. 마우스만 올리면 펼쳐져도 `aria-expanded="false"`이며, Esc 처리 조건에도 들어가지 않는다. 클릭으로 연 뒤 Esc를 눌러도 포인터가 메뉴 위에 있으면 CSS 때문에 계속 표시된다. 버튼을 다시 눌러 닫는 경우도 동일하다.
- 재현: hover 가능한 861px 이상 화면에서 People에 마우스를 올리고 클릭하지 않는다. 메뉴가 보이지만 `aria-expanded`는 false다. 포인터를 유지한 채 버튼에 키보드 포커스를 주고 Esc를 눌러도 닫히지 않는다. 클릭→Esc에서는 속성만 닫힌 상태로 바뀌고 메뉴는 남는다. 상태 불일치는 JS 모의 실행과 CSS 조건으로 확인했다.
- 수정안: JS 활성화 시 hover·클릭·Esc를 하나의 상태 관리 함수로 연결한다. CSS hover는 `.nav-dd:not(.dd-js):hover`로 제한하고, Esc나 재클릭으로 닫은 뒤에는 포인터가 나갔다 다시 들어오기 전까지 hover 재열림을 억제한다.

### 2. [중간] 커버 기사 링크에서 방향키를 누르면 포커스 대상이 inert로 바뀜
- 위치: `themes/t5.v02/assets/t5.js:46`, `themes/t5.v02/assets/t5.js:56`
- 문제: 트랙의 `keydown`이 내부 기사 링크에서 발생한 방향키도 처리한다. 이동 중 현재 번호가 바뀌면 기존 슬라이드 전체를 `inert`로 만들지만, 내부 링크에 있던 포커스를 옮기는 처리가 없다. 따라서 키보드로 기사를 넘길 때 포커스가 유효한 탐색 대상에 유지되지 않는다.
- 재현: 홈에서 Tab으로 트랙을 거쳐 첫 커버의 기사 링크에 포커스한 뒤 →를 누른다. 다음 슬라이드로 이동하면서 기존 링크의 부모가 `inert`가 된다. 모의 실행에서도 이동량이 한 칸의 절반을 넘자 번호가 2로 바뀌고 첫 슬라이드가 inert가 되는 것을 확인했다. 이 경로에는 포커스 이전 코드가 없다.
- 수정안: 내부 링크에서 방향키로 이동할 때 먼저 `track.focus({preventScroll: true})`로 포커스를 트랙에 옮긴다. 또는 슬라이드를 inert로 만들기 전에 내부 포커스 유무를 검사해 트랙으로 이전한다.
